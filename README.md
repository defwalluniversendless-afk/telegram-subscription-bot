# Бот платной подписки на закрытый Telegram-канал

Бот принимает оплату через ЮKassa, выдаёт одноразовую ссылку в закрытый канал, напоминает о продлении и закрывает доступ после окончания подписки.

## Подготовка

1. Создайте бота через @BotFather и получите `BOT_TOKEN`.
2. Добавьте бота администратором закрытого канала с правами приглашать и блокировать пользователей. Укажите `CHANNEL_ID` (обычно начинается с `-100`) и свой Telegram ID в `ADMIN_ID`.
3. Для настоящих оплат настройте магазин ЮKassa и получите `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET`.
4. Создайте локальный `.env` из шаблона и заполните параметры:

   ```sh
   cp .env.example .env
   ```

   **Не добавляйте `.env` в Git и никому не отправляйте его:** файл содержит токен Telegram и ключ ЮKassa. В репозитории хранится только `.env.example` без секретов.

## Запуск

```sh
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python bot.py
```

Для настоящих тестовых платежей через ЮKassa возьмите тестовые `shop ID` и секретный ключ в кабинете ЮKassa в разделе тестового магазина/API-ключей и задайте их в переменных окружения (`YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET`). При этом укажите `TEST_MODE=0`: бот создаст платёж в ЮKassa и получит подтверждение об оплате. Не используйте здесь ключи рабочего магазина, если хотите тестировать без списания реальных денег.

`TEST_MODE=1` — отдельный режим локальной имитации без ЮKassa: оплатить сможет только администратор, и реального тестового платежа не будет. Для рабочих оплат также укажите `TEST_MODE=0`, но используйте ключи рабочего магазина. После изменения переменных окружения перезапустите бота. Для постоянной работы запустите бота на сервере или другой подходящей хостинг-платформе: сам GitHub не запускает этот бот.

## Команды

- Пользователи: `/start`, `/status`, `/cancel`.
- Администратор: `/users` (список и управление подписками), `/grant ID дни` (выдать доступ вручную), `/del @username` или `/del Telegram_ID` (сбросить подписку и удалить пользователя из канала), `/all текст` (рассылка всем), `/all_sub текст` (рассылка активным подписчикам), `/block @username` или `/block Telegram_ID` (заблокировать в боте и удалить из канала), `/unblock @username` или `/unblock Telegram_ID` (снять блокировку), `/stats`.
- `/menu` открывает админ-панель со статистикой, техрежимом и выбором магазина ЮKassa.

Новая или пустая база при первом запуске автоматически включается в техрежим: приём оплаты и автосписания приостановлены, пока администратор не включит бота в `/menu`. В уже используемой базе сохранённый статус техрежима не меняется при перезапуске.

При включении техработы бот приостанавливает автоматические списания, оплату/продление через бота и проверку сроков подписки; подписки остаются в базе. Уже созданный в ЮKassa платёж может завершиться независимо от бота. После выключения техработ активные подписки продолжают работать по прежнему сценарию. Пользователям, чей срок закончился во время техработ, бот отправит сообщение с кнопкой продления и даст 3 дня; затем неоплатившие будут удалены из канала и получат сообщение, что доступ восстановится после оплаты.

Для переключения магазина через `/menu` задайте в окружении отдельные пары `YOOKASSA_TEST_SHOP_ID`/`YOOKASSA_TEST_SECRET` и `YOOKASSA_LIVE_SHOP_ID`/`YOOKASSA_LIVE_SECRET`. Начальный выбор задаётся `PAYMENT_STORE_MODE=test` или `live`; дальнейший выбор панели сохраняется в `bot.db`. Старые `YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET` остаются совместимы как ключи одного магазина, указанного в `PAYMENT_STORE_MODE`. Не включайте реальный магазин, пока не проверили рабочие ключи: новые платежи будут настоящими.

База пользователей и сроки подписок общие для тестового и реального магазина. Сохранённый способ оплаты принадлежит конкретному магазину и не переносится при переключении; активные автосписания учитываются и запускаются только в том магазине, где карта была привязана. Незавершённые платежи/привязки проверяются с ключами исходного магазина.

В `/users` администратор может посмотреть пользователей и срок подписки, продлить подписку на 30 дней, установить срок окончания через произвольное число дней от текущей даты или сбросить подписку и удалить пользователя из канала. Кнопка «Написать пользователю» позволяет начать переписку: ответьте на запрос бота текстом или медиа; пользователь может отвечать реплаем на сообщения бота, а администратор — реплаем на полученные ответы. Связи сообщений хранятся в базе и сохраняются после перезапуска. Список разбит на страницы; команда и кнопки управления доступны только администратору.

Бот уведомляет администратора о каждой успешной оплате и раз в день присылает число новых пользователей за текущий день (время UTC). В `/status` пользователь видит срок подписки и состояние автосписания, а также может включить/отключить его, изменить или удалить сохранённый способ оплаты либо связаться с администратором. Удаление способа оплаты стирает его идентификатор из базы бота и отключает будущие автосписания; оно не отменяет уже созданный платёж. После покупки пользователь получает срок подписки, состояние автосписания и подсказку открыть `/status`; состояние автосписания также отображается в `/users` для каждой записи. Ручная успешная оплата добавляет период к текущей дате окончания, не обнуляя оставшиеся дни.

Автосписание работает отдельно от ручного продления: задайте `AUTOCHARGE=1`, используйте `TEST_MODE=0` и ключи нужного магазина ЮKassa. В `/status` можно изменить способ оплаты с продлением (спишется стоимость периода и к сроку добавится настроенный период) либо привязать карту на нулевую сумму без списания и без изменения срока подписки. Для нулевой привязки ЮKassa проверяет карту и сохраняет способ; после этого пользователь может отдельно включить автосписание. Нулевая привязка поддерживается ЮKassa в тестовом магазине по умолчанию; для рабочего магазина автоплатежи нужно подключить через менеджера ЮKassa. Способ оплаты сохраняется только после подтверждения ЮKassa (`status=active`, `saved=true`). Если включили автосписание уже после первой оплаты, привяжите карту через нулевую форму и включите его в `/status`. При попытке списания бот проверяет платёж у ЮKassa; ошибки проверки и отменённые повторные платежи записываются в журнал, а пользователь получает сообщение о неудачной попытке. `/stats` показывает число активных подписок с сохранённым способом оплаты и ожидающих автоплатежей.

`/block` не может запретить человеку снова открыть чат с ботом на уровне Telegram: он сохраняет пользователя в базе как заблокированного, блокирует обработку его сообщений и кнопок и удаляет из канала. Запись остаётся для истории; администратор может снять ограничение через `/unblock`.
